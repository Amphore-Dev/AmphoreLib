# 🧩 Filters Context

A generic React context for managing **application filters** (with per-domain slices), persisted in `sessionStorage`/`localStorage` and optionally synced with the URL.

---

## ✨ Features

- `createFiltersContext<T>()` → generates a **Provider** and a `useFiltersContext` hook.
- Each **slice** of `T` is a filters object (`TFiltersSlice`).
- **Common filters** included automatically in every slice (`TDefaultFilters`):
  `page`, `limit`, `total`, `status`, `search`, `sortOrder`, `sortType`, `count`, `startDate`, `endDate`.
- Automatic persistence (`sessionStorage` by default, `localStorage` optionally) — writes guarded by try/catch, never throws (SSR, private browsing, storage full/blocked).
- Optional URL sync via `params` + `TParamsCodecs`, with no dependency on any router (default adapter based on `window.history`/`URLSearchParams`).

---

## 🛠️ Usage

### 1. Define your filter types

```ts
// src/types/TFilters.ts
import { TFiltersSlice } from "@amphore-dev/amphore-lib";

export type TMyFilters = {
  planning: TPlanningFilters;
  orders: TOrdersFilters;
};

export type TPlanningFilters = TFiltersSlice<{
  display?: "day" | "week";
  site?: string | null;
}>;

export type TOrdersFilters = TFiltersSlice<{
  status?: "draft" | "sent";
  assignedTo?: string;
}>;
```

### 2. Define your default values

```ts
export const DEFAULT_FILTERS: TMyFilters = {
  planning: { display: "week", site: null },
  orders: { status: "draft", assignedTo: "" },
};
```

### 3. Create a typed context

```ts
// src/contexts/FiltersContext.ts
import { createFiltersContext } from "@amphore-dev/amphore-lib";
import { TMyFilters } from "@myTypes";

export const { Provider: FiltersProvider, useFiltersContext } =
  createFiltersContext<TMyFilters>();
```

### 4. Wrap the app or the page

```tsx
import { DEFAULT_FILTERS } from "@myConstants";
import { FiltersProvider } from "@myContexts/FiltersContext";

<FiltersProvider defaultFilters={DEFAULT_FILTERS}>
  <App />
</FiltersProvider>;
```

⚠️ Avoid nesting a `Provider` inside another `Provider` to limit context errors.

### 5. Use the filters in a component

```tsx
import { useFiltersContext } from "@myContexts/FiltersContext";

function PlanningToolbar() {
  const { filters, setFilter } = useFiltersContext("planning");

  return (
    <>
      <span>View: {filters.display}</span>
      <Button onClick={() => setFilter("display", "day")}>Day</Button>
      <Button onClick={() => setFilter("display", "week")}>Week</Button>
    </>
  );
}
```

### 6. URL adapter (only if `updateUrlParams` is used)

By default, the `Provider` uses `useStandaloneSearchParams` — an adapter based on `window.history`/`URLSearchParams`, with no dependency on any router.

To plug in a different router (React Router, etc.), supply your own adapter via `adapterHook`, matching this interface:

```ts
interface ISearchParamsAdapter {
  getParam: (key: string) => string | undefined;
  setParams: (
    updater: (prev: URLSearchParams) => URLSearchParams,
    options?: { replace?: boolean }
  ) => void;
}
```

```tsx
const myRouterAdapter = (): ISearchParamsAdapter => {
  const [searchParams, setSearchParams] = useSearchParams(); // e.g.: react-router-dom
  return {
    getParam: (key) => searchParams.get(key) ?? undefined,
    setParams: (updater, { replace = true } = {}) => {
      setSearchParams(updater(new URLSearchParams(searchParams)), { replace });
    },
  };
};

<FiltersProvider defaultFilters={DEFAULT_FILTERS} adapterHook={myRouterAdapter()}>
  <App />
</FiltersProvider>;
```

## 🧩 `useFiltersContext` hook API

```ts
interface IUseFiltersContext<T, K, S = T[K]> {
  filters: S;
  filtersKey: K;
  setFilters: (next: S | ((prev: S) => S), replace?: boolean) => void;
  setFilter: <SK extends keyof S>(key: SK, value: S[SK]) => void;

  getPagination: () => Partial<{ page: number; limit: number; total: number }>;
  setPagination: (p: Partial<{ page: number; limit: number; total: number }>) => void;

  count: number;
  setCount: (n: number) => void;

  getParams: (filters?: S) => Record<string, string>;
  getQueryKeys: (filters?: S) => string[];

  options?: TFiltersContextOptions<S>;
  fieldRenderers?: Partial<TFieldRendererMap>;
}
```

- `filters`: the current filters state for the slice
- `setFilters(next, replace?)`: replaces or updates the filters (object or function)
- `setFilter(key, value)`: updates a single key
- `getPagination()` / `setPagination(p)`: read/write `{page, limit, total}`
- `getParams(filters?)` / `getQueryKeys(filters?)`: serialization to the URL / query keys
- `count` / `setCount(n)`: active-filters counter (prefer `countCallback` in options over manually calling `setCount`)
- `fieldRenderers`: see [Concepts/Fields](?path=/docs/concepts-fields--docs), `FiltersContext` level

## ⚙️ Options (`TFiltersContextOptions<S>`)

```ts
type TFiltersContextOptions<S> = {
  countCallback?: (filters: S) => number;
  defaultValues?: Partial<S>; // defaults LOCAL to the calling component
  params?: Partial<TParamsCodecs<S>>; // state <-> URL mapping
  resetPageOnChange?: boolean; // default: true
  updateUrlParams?: boolean; // default: false — explicit opt-in
  skipInitFromUrl?: boolean; // skips the initial read from the URL
};
```

⚠️ The `options` (including `defaultValues`) are **local** to the component that passes them to `useFiltersContext` — they aren't shared between several components consuming the same slice. For global default values, pass them into the `Provider`'s `defaultFilters` instead.

### The `params` option

Each key can be `true` (value encoded as-is) or an object `{ get?, set?, key? }`:

```ts
const { filters } = useFiltersContext("planning", {
  updateUrlParams: true,
  params: {
    site: {
      key: "siteId", // key used in the URL, e.g.: ?siteId=1
      get: (value) => value?.id, // value -> URL
      set: (raw) => ({ id: raw }), // URL -> value
    },
    status: true, // encoded as-is, e.g.: ?status=draft
  },
});
```

## 📖 Full example

```tsx
function OrdersList() {
  const { filters, setFilter, getPagination } = useFiltersContext("orders", {
    updateUrlParams: true,
    defaultValues: { limit: 20 },
    params: { status: true, assignedTo: { key: "user" } },
  });

  useEffect(() => {
    fetchData(filters, getPagination());
  }, [filters]);

  return (
    <Select
      value={filters.status}
      onChange={(value) => setFilter("status", value)}
      options={[
        { label: "Draft", value: "draft" },
        { label: "Sent", value: "sent" },
      ]}
    />
  );
}
```

## 📕 Glossary

- **Slice**: the portion of filters state corresponding to a domain (e.g., `planning`, `orders`).
- **Adapter (URL)**: an object `{getParam, setParams}` syncing state with the URL, with no dependency on any particular router.
- **Codec**: defines how a filter key serializes/deserializes to and from the URL (`TParamCodec`).
- **Provider**: a React component wrapping the app (or part of it) to supply the filters context.
